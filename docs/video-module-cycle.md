# 新旧内容循环推进提醒

本功能仅提供学习流程提醒，不判断学习、分组或复习是否完成。

## 显示条件

在 `video-learning-ui.js` 中，阶段二 `continuous` 的第3步「独立重做」（索引2），或阶段三 `question` 的最后一步，直接渲染同一个 `moduleReminder` 组件。提醒放在该步骤原有内容和操作按钮下方，无需展开或额外确认；首页、阶段一和其他步骤不显示。阶段二第3步的下一步预览显示「卡住的题目进入逐题突破，没问题的点击下方进入分组训练」，实际第4步名称和导航不变。

提醒正文：

> 完成当前知识模块的视频学习后，将资料推进分组训练，按照原有学习机制完成新旧内容的循环训练，再继续学习新视频。

不再显示绿色成功卡片，也不再依赖资料创建、Run 启动、`moduleCycle`、`sourceStage` 或任何完成状态。

## 按钮与业务边界

- 金色「进入新增资料分组」调用与首页相同的 `PocketLearning.openHomeGrouping`，是阶段二第3步及阶段三末步唯一的分组入口；不检测或标记学习、分组或复习完成。
- 「开始新视频学习」只将原有阶段一操作位置保存为第一步，然后进入「知识模块速通」。不检测完成条件，不改变阶段二、阶段三、题号、已有资料或 Group/Run 进度。
- 首页「新增资料分组」、阶段二第3步及阶段三末步「进入新增资料分组」调用同一个 `PocketLearning.openHomeGrouping`。不绑定、改写资料草稿的来源。已有草稿仍按原机制恢复；已有未完成任务、今日复习和资料间复习的创建保护均保持不变。
- 阶段二第3步显示「当前知识模块视频学习已完成，若不用进入逐道题突破，可自行选择推入到分组训练。」作为静态提示，不作完成检测。阶段三不增加这句提示。
- 移除所有步骤下方原灰色进度说明和通用「进入题目分组」按钮；仅保留上述位置的新命名入口，步骤导航和题号逻辑不变。

## 数据兼容

不新增存储字段或 key。已存的 `videoLearning.moduleCycle`、`sourceStage`、草稿 `videoModuleId` 不作清理或迁移，不再用于提醒判断；原始字段随现有主状态与完整备份保留。正式资料创建仍执行原有事务和 Run 启动逻辑，不再额外写入视频完成状态。

## 验证

`video-module-cycle.test.cjs` 检查步骤、题号、旧字段保留、保存失败和备份。`video-module-cycle.browser.cjs` 使用 localhost 临时数据验证空资料、未完成任务、复习未完成及旧完成记录下的无条件提醒，两个按钮、资料创建保护、刷新及手机桌面布局。真实 Firebase、安装版 PWA 与离线能力不在本地隔离测试范围内。
