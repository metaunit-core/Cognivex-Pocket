# 仅修改今后的复习分组

「更改资料 → 追加题目与分组 → 改分组情况」采用方案 B。

- `material.groups`、原创建时间、原学习完成状态、Run、重点题来源和学习次数均不重建。
- `material.reviewGrouping` 为可选的版本化复习布局，包含 `version: 1`、`activeId` 和 `layouts`。每个布局保存独立 ID、创建时间、每组题数和独立的复习 Group/Run。
- 新建每日复习、资料间复习和选做重学任务时使用当前布局。原新学及追加学习继续使用原 Group 和原调度器；重点复习系统仍使用原题目身份。
- 复习队列保存 `reviewLayoutId`，旧布局不删除；已完成队列不改写。布局中没有新学完成标记，也不复制原 Group 的成绩。
- 重点题勾选按题号映射回原 Group，保留原重点题 ID、掌握状态和历史。
- 当前有效题目以原 Group 的有效 `questionRange` 为准，没有该字段时读取 `start/end`。非连续题号保留原保存顺序；重复题号、重复 ID、空范围、异常版本或超过 10000 道题时拒绝提交。
- 后续追加仍使用原追加规则，新追加题目在原学习完成后按追加分组进入复习；需要统一划分时可再次修改复习分组。题目移除后，复习视图过滤已移除题号，历史布局及其执行记录保留。
- 活动主任务、资料间复习、未完成每日复习、待完成的新学复习义务及涉及本资料的重学任务会阻止提交，不清除或移动断点。
- 通过现有 `PocketStorage.updateState` 一次保存整个版本与状态，保留过期窗口检查和保存失败回滚。修改布局不产生学习完成事件、不增加学习次数、不改变每日复习完成记录；已合法获得的新增权限随当前布局保持有效。
- JSON/Firebase 继续携带完整原始主状态，不更换备份协议。旧数据没有 `reviewGrouping` 时完全沿用旧分组。新增布局需用支持该字段的应用版本恢复和运行；旧版应用不会应用新复习布局。
